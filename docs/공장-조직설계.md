# 집 PC 공장 — 조직 설계도 (체계)

*2026-11-10 · 살아있는 문서(설계 중 계속 갱신). 인프라·설치는 `집PC-공장-로드맵.md`, 설치 패키지는 `../local-factory/`.*
*대표가 "백지에서 한땀씩" 설계 중. 경제 블로그를 템플릿으로 세우고 다른 제품으로 확장.*

## 조직 (2층 — 사업부 + 그 안의 본부)
```
대표 (CEO) — 결정·발행
 └ 운영총괄 (Claude/COO) — 전체 지휘(허브)
     ├ 기술보안팀   ← 크로스커팅: 인프라 안정성 감시·권한승인·로그인알림 (공장 안 멈추게)
     ├ 경제사업부  ← 마스터 템플릿 (완성 후 수평복제의 기준)
     │    ├ 전략본부(비서실)  — 경제 + 인플TF 담당 (아래)
     │    ├ 분석본부          — 키워드담당 + 제목담당 + 분석총괄 (아래)
     │    └ 생산본부          — 조사·글·검수(QC)·사진·저장 (아래)
     ├ 인플 준비 TF  — 경제 위에 올라탐(정책 렌즈). 경제 비서실·분석본부 겸임. 주 2~3편.
     ├ 패션사업부    — 사복(캐시미어다이어리). 기존 체계 유지 + 저장 어사이드 + 보완컷 ComfyUI.
     └ 연예사업부    — 연예패션(남는블로그) + 가십(연예스토리·스타연예) 묶음. 기존 체계 유지 + 저장 어사이드.
   (쇼츠/유튜브 = 계열사. 지금 설계 제외, 다른 세션에서 구축 중.)
```
- **경제사업부만 풀 구조**(전략·분석·생산). 비서실은 경제에만 두고 **경제 + 인플TF**만 챙긴다.
- **패션·연예는 수익 한방** → 비서실 X, **가벼운 분석(선정·트렌드만)**, 성과로그·KPI 없음, **생산 중심.**

## ★ 실행 모델 — 손발(어사이드) vs 두뇌(Claude) · 바통=드라이브 (2026-11-10 대표 확정, 최상위 원칙)
공장엔 **두 선수**가 있고 **서로 직접 조종하지 않는다.** 바통은 **드라이브 파일**로만 넘긴다.

```
어사이드(손발·브라우저)  →  드라이브  →  Claude 공장(두뇌)  →  드라이브  →  어사이드(저장)
```

- **어사이드 = 손발 (브라우저 일 전부).** 그록 웹 조사·사진 수집, **내 블로그 읽기(발행이력·성과 통계)**, 네이버 조립·임시저장. 브라우저로 하는 건 **다 어사이드.** (대표가 어사이드를 돌리고, 어사이드가 그록·네이버를 구동. 어사이드가 이미 이 일을 제일 잘함.)
- **Claude 공장 = 두뇌 (브라우저 0).** 분석(키워드·제목·총괄·비서실), **글쓰기(스킬·말투)**, 사진(로컬 GPU/ComfyUI **API** — 브라우저 아님), 검수, 순환검증, 오케스트레이션. **드라이브 파일만 읽고 쓴다.**
- **🚫 Claude는 브라우저(네이버·그록·크롬확장)를 직접 조종하지 않는다.** 이유 ① 어사이드가 그 일을 더 잘하고 이미 됨 ② 네이버 로그인·발행 자동화 금지 철칙. (크롬확장으로 Claude가 긁게 하려던 시도 = 폐기.)
- **바통 = 드라이브 파일.** 어사이드가 결과를 드라이브에 떨구면 Claude가 받고, Claude가 산출물을 드라이브에 올리면 어사이드가 집어간다. (경로 = '작업대' 장.)
- **트리거:** 어사이드를 **돌리는 건 대표(또는 어사이드 자체).** Claude는 **"드라이브에 뭐가 들어왔나"만 보고** 움직인다 — 어사이드를 시키지 않는다. → 공장은 어사이드가 어떻게 켜지든 무관하게, **드라이브에 올라온 것**을 처리.
- **한 줄:** 어사이드만 쓰면 **대표가 머리까지 다 써야** 한다. 공장은 그 **머리 쓰는 일(전략·선정·글·검수·분석)을 Claude가** 대신하고, **손발은 어사이드 그대로.**

### 실행 연결 — 드라이브가 '어사이드 내부 ↔ 외부 Claude Code' 통로 (A방향, 2026-11-11 확정)
그록은 **API가 아니라 웹**이고 **어사이드 안**에서 돈다. 외부의 Claude Code와는 **직접 대화하지 않는다.** → **어사이드가 다리:** 그록 웹 결과를 받아 **드라이브에 내려놓고**, Claude Code가 외부에서 집어간다. (어사이드는 이미 구글시트에 쓰므로 드라이브 저장 능력 검증됨.)
```
어사이드: 그록 조사 → 드라이브 N_조사.md 저장  (기존 '클로드 웹에 붙여넣기'를 '드라이브 저장'으로 — 목적지만 변경)
Claude Code(외부): N_조사.md 읽음 → 글·제목(후킹)·검수 → N_원고.md
어사이드: N_원고.md 읽어 네이버 저장
```
- **점진 이전(폴백 유지):** ①분석·제목 후킹 생성(Claude Code, 저위험) → ②글 하루 1편 Claude Code로 품질 비교 → ③검수·순환검증 이전. **기존 어사이드 올인원 루틴은 1주 검증까지 폴백으로 안 지움**(공장 안 멈춤).
- **전제:** 무인 가동이라 대표가 못 본다 → **상태판·리모트가 눈.** 첫 관문 = 1바퀴 테스트를 대표가 지켜보며 1회.
- 할 일: `aside-경제-루틴-자동`을 **수집(→드라이브) / 저장(드라이브→네이버)** 둘로 쪼갬.

> **바통 두 종류 (둘 다 작동 중):** ① **작업대 파일(.md)** = 조사·원고·사진·상태판·지시함 → 구글드라이브. ② **표(시트)** = 성과로그·발행이력·아카이브·인플로그 → 어사이드가 구글시트에 쓰고 **Claude가 읽는다(이미 기존 체계로 하고 있음 — 대표 확인 2026-11-10).** 서비스계정(C)은 성과 분석 본격화 때 선택적으로, go-live 전제 아님.

## 사업부별 구성 (수평복제 — 2026-11-10 인터뷰 확정)
| 사업부 | 비서실 | 분석 | 사진 | 저장 | 기존 프롬프트(단일 소스) |
|---|---|---|---|---|---|
| **경제** | O | 풀(키워드·제목·총괄 + 성과로그·KPI) | 썸네일=원본+GPU / 본문=GPU 실사생성 | 어사이드 | 클로드-경제-글, 그록-경제-조사/부동산조사/사진수집, 지피티-경제-사진, aside-경제-루틴 |
| **인플 TF** | 경제 비서실 겸임 | 경제 분석본부 겸임 | 경제와 동일(GPU) | 어사이드 | 클로드-인플-부동산 + 정책 캘린더 + 주간 정책 스캔 + 인플로그 |
| **패션** | X | 가벼움(최근 사복 셀럽·사건 선정) | **셀럽 실물 유지 + 보완컷만 ComfyUI**(지피티 대체) | 어사이드 | 그록-패션-조사사진, 클로드-패션-글, aside-패션-루틴 |
| **연예** | X | 가벼움(유입트렌드 선정) | 셀럽 실물 + **보완컷 ComfyUI**(지피티 폐기) | 어사이드 | (연예패션)클로드-연예패션-글·그록-연예패션-조사·aside-연예패션-루틴 / (가십)클로드-연예스토리·스타연예-글 등 |
- 핵심: **남은 두 사업부는 기존 체계 그대로, '저장=어사이드' + '보완컷=ComfyUI'만 공통 변경.**
- **지피티 완전 폐기:** 사진은 전부 GPU(썸네일 img2img / 본문·보완컷 text2img), 제목·본문은 이미 클로드로 이관. 레거시 지피티 탭(경제 글사진/제목, 패션·연예 보완사진 등)은 참고용으로만 남기고 루틴에서 제외.

## 발행 편수 · 부하 (2026-11-10 대표)
- **모든 사업부 하루 5편 기본.** (인플 TF만 주 2~3편 예외.) **추가 = 대표가 운영총괄에게 키워드 요청 시** 그 키워드로 추가 생산.
- **부하 방침(현실 — 거의 전부 병렬 가능):**
  - **LLM(글·분석·제목) = 병렬** (Anthropic 서버서 돌아 로컬 부하 거의 0, 구독 주간 캡만 주의).
  - **저장 = 어사이드로 병렬** — 프로필(계정)별 3창 병렬(검증됨). 크롬확장은 에이전트 하나라 순차·불확실이라 안 씀(2026-11-10 확정). 어사이드가 멈추면 `기술보안팀`이 **드라이브로 감지→상태판 기록→대표 알림**(브라우저는 Claude가 못 누름, 아래 '실행 모델').
  - **GPU 사진 = 유일한 단일 큐, 근데 가벼움.** 하루 실제 ~**40장**(경제 30+썸5 / 패션 보완 ~5 / 연예 보완 ~5 — 패션·연예는 실물 중심) → GPU **20~40분**. 병목 아님.
  - 본부별 정확한 시각 배치는 추후(겹침 최소화 목적이나, 이 부하면 병렬로 돌려도 무방).

## 전략본부 (= 대표 비서실)
- 분석본부 날것을 대표가 **보고 바로 판단하게** 요약·브리핑.
- 대표가 **이미 아는 것(조회수·발행편수)은 빼고**, **못 보거나 챙기기 번거로운 "숨은 것"**을 파냄.
- 단순 보고 X → **KPI 대비 방향, 대표가 생각·고려할 점까지 조언.**
- **시점별로 뭘 보고할지는 본부가 스스로 판단**(일=가볍게, 주=리포트, 월=결산). 톤은 읽기 쉽게.

## 분석본부
- **분석총괄(lead):** 성과로그 전체 조망 → 두 담당 결과 **종합해 제안 1개** → 대표. **순환 검증**(지난 제안이 먹혔나 재평가 / PDCA).
- **키워드 담당:** 뭘 쓸지. 핫키워드 선정 + **도전 키워드 1편 제안**(대표 승인) + 참고 인플에서 **빈틈 주제**.
- **제목 담당:** **후킹 학습 루프** — ①매일 참고 인플 제목에서 ""·'' 후킹을 뽑아 **후킹 라이브러리**(8메커니즘) 누적 → ③오늘 글에 응용해 **서로 다른 결의 후보 N개** → ④발행 성과로 터진 후킹 **강화**(가중 ↑/↓). 유형 분류·인플 비교도 겸함. 재료=`prompts/project/후킹-라이브러리.md`.

## 생산본부
글 한 편의 공정: 조사 → 글 → 사진 → 저장.
```
생산총괄
 ├ 조사 담당   (그록 — 현재 사실·단지 실거래·사연)
 ├ 글 담당     (클로드 — 제목+본문, 스킬: money-content-writer + blog-voice)
 ├ 사진 담당   (로컬 GPU/ComfyUI + 클로드 장면 프롬프트)
 ├ 검수 담당   (QC — 지침 준수 재검토, 저장 전 게이트)
 └ 저장 담당   (네이버 임시저장 = 어사이드)
```
- **검수 담당(QC):** 완성 초안이 '지침대로' 됐는지(글 프롬프트·사진 규칙·서식·사실범위·공개수위) 저장 전 재검토 → '가끔 이상한' 초안을 걸러냄. 사소한 건 교정, 판단 필요하면 담당에 되돌림.
- **저장 담당 = 어사이드**(2026-11-10 확정 — 검증·3창 병렬). 크롬확장은 에이전트 하나라 순차·불확실이라 철회. 어사이드가 멈추면 **`기술보안팀`이 드라이브로 감지→상태판 기록→대표 알림**(Claude는 브라우저 못 누름 — '실행 모델'). 비번 자동로그인은 X — 대표만.
- **임시저장까지만. 발행은 대표.**

## 본부간 협업체계 (운영총괄 직접 지휘 = 허브)
본부끼리 **직접 대화 X.** **산출물(문서·시트)로 넘기고, 운영총괄(COO)이 순서를 돌리고 조정**한다. 닫힌 루프(PDCA).
```
분석본부 ─「오늘 생산지시」→ 생산본부 ─임시저장→ 대표(발행)
   ▲                                              │
성과로그 ←─ 어사이드(발행결과 기록) ←─────────────┘
   │
   └→ 분석본부(평가) ─「분석 종합」→ 전략본부 ─「브리핑」→ 대표
```
| 본부 | 읽는 것 | 내놓는 것(핸드오프) |
|---|---|---|
| 분석본부 | 성과로그·참고인플 | 「오늘 생산지시」(키워드5+제목유형 권고+도전1) |
| 생산본부 | 오늘 생산지시 | 임시저장 글 + 생산로그 |
| 어사이드 | 발행 결과 | 성과로그 |
| 분석본부 | 성과로그 | 「분석 종합」 |
| 전략본부 | 분석 종합 | 「대표 브리핑」(일/주/월) |
- **운영총괄 = 지휘자:** 각 본부 제때 깨움, 충돌 조정, 핸드오프 누락 감시. 본부는 서로 직접 호출하지 않음(허브-앤-스포크).

## 작업대 (구글드라이브 — 바통 주고받는 곳) ★2026-11-10 확정
어사이드(브라우저: 그록웹·네이버)와 Claude(글·분석·검수·GPU)는 **서로 직접 안 만나고 드라이브로** 일을 주고받는다. 드라이브를 **두 구역**으로 나눈다.

```
📁 공장
├─ 📁 작업대   ← 오늘 만드는 중 (바통). 매일 비우고 새로 채움.
│   └─ 경제 / 패션 / 연예 …(사업부별) / 오늘/
└─ 📁 기록     ← 끝난 것 (발행로그·성과로그). 분석본부·비서실이 읽음.
```

**한 편(1 글)이 작업대에서 거치는 순서 = 파일로:**
```
경제/오늘/
├─ 1_조사.md    (어사이드가 올림: 그록 조사·사진수집 결과)
├─ 1_원고.md    (Claude 글담당이 올림)
├─ 1_사진/      (Claude 사진담당이 올림: GPU 생성물)
└─ 1_완료       (검수 통과 신호 — 이거 뜨면 "어사이드야 저장해도 돼")
```

- **규칙:** 각 담당은 **앞 담당이 파일 올렸는지만** 보고 움직인다(서로 안 부딪힘). 운영총괄(허브)이 순서만 돌린다.
- **신호 = 파일 이름.** `N_완료`가 뜨기 전엔 어사이드는 저장 안 함. (별도 시스템 불필요.)
- **읽고/쓰는 위치는 각 담당 지시서에 한 줄로 명시**(아래 '본부간 협업체계' + 각 에이전트).
- **접근:** 어사이드=드라이브에 올리기/집기, Claude=구글시트·드라이브 MCP로 읽고 쓰기. **키·로그인은 기술보안팀**(구글은 서비스계정, 네이버는 대표).
- 지금 드라이브엔 발행로그만 있음(추정) → **go-live 세팅 때 위 두 구역으로 새로 깐다.**

## 상태판 · 지시함 (대표가 밖에서 — 2026-11-10 확정)
대표는 **휴대폰**만 쓰고 PC 앞에 없을 때가 많다. 그래서 "공장 상태 확인"과 "까먹기 전 지시"를 두 파일로 푼다. 둘 다 **드라이브**에 둬서 **PC가 꺼져 있어도** 남아 있고, 대표는 **리모트로 운영총괄에게 말로 묻거나** 파일을 직접 연다.

**① 지시함 (드라이브 `지시함.md`) — 던져두기**
- 대표가 폰에서 **한 줄씩 추가**(날짜·내용). 예: `11/10 종목글에 2차전지 하나 넣어줘`.
- 운영총괄이 **매 하루운영 '새벽' 맨 처음** 지시함을 읽어 → 그날 생산지시·소견에 반영 → 반영한 줄에 `[반영 날짜]` 표시(중복 반영 방지).
- **PC 꺼져 있어도** 메모는 드라이브에 남았다가 **다음 run에 집어감.** → "까먹기 전에"가 풀린다.

**② 상태판 (드라이브 `상태.md`) — 지켜보기**
- 운영총괄이 **각 단계 끝날 때 한 줄씩** 남긴다. 예: `08:00 조사 5/5 ✅ / 09:10 글 3/5 진행 / 09:40 🔴 4번 사진 멈춤-로그인풀림(기술보안팀 조치중)`.
- **기술보안팀**이 멈춤·로그인 풀림·단계 실패를 감지하면 **🔴 + 시각 + 이유 + 조치**를 상태판에 쓴다.
- 대표는 폰에서 **"공장 상태 알려줘"** 하면 운영총괄이 상태판을 읽어 요약; 직접 열어 봐도 된다. → "됐나/멈췄나/왜"가 풀린다.
- (선택) 🔴 뜨면 **폰 푸시 알림**까지 연결 가능 — go-live 후 필요하면 추가.

> 요지: 대표는 **드라이브를 뒤지지 않는다.** 폰에서 **운영총괄에게 말로** 묻고 지시한다(리모트). 드라이브는 공장이 쓰는 뒷창고 + PC 꺼졌을 때의 보관함.

## 운영 리듬 (하루 시계)
| 시각 | 누가 | 뭐 |
|---|---|---|
| 새벽(~4시) | 분석본부 | 「오늘 생산지시」(키워드5 + 제목유형 권고 + 도전1) |
| 오전 | 생산본부 | 5편 생산 → **검수(QC)** → 네이버 임시저장(어사이드) |
| 오전~낮 | 대표 | 제목 골라 발행(띄엄띄엄) |
| 발행 후 | 어사이드 | 성과 기록(성과로그) |
| **17:00** | **전략본부(비서실)** | **퇴근길 브리핑**(숨은 것 + KPI 대비 조언) ← 대표 지정 |
| 월요일 아침 | 전략본부 | 주간 리포트 (한 주 성과 분석 + 다음 주 방향) |
| 상시 | 기술보안팀 | 권한 승인·로그인 풀림·멈춤 감지→복구 또는 즉시 알림 |
- **17시 브리핑 = 당일 글 성과 보고가 아님**(홈판 시차 median 4일 → 당일 무의미). **쌓인 데이터에서 파낸 인사이트·생각거리.**

## 키워드 선정 로직 (날 단위)
- **핫키워드 날**(5편 다 핫) ↔ **틈새표 날**(5편 다 틈새), **2일 간격 교대.**
- 핫키워드 = **조회수 데이터에서 자동 선정**(분석본부). 같은 핫키워드는 2일 간격 재사용.
- 틈새표 = 기존 방식(검색량 상위 + 부동산3·바이오2 + 2일 중복제외).
- 가끔 **도전 키워드 1편**을 에이전트가 이유와 함께 제안 → 대표 승인 시 반영.

## KPI 뼈대
- **북극성(결과) = 애드포스트 수익.**
- **선행 = 조회수**(직접 미는 레버, 수익을 끌어올림).
- **돈줄 드라이버 = 홈판 노출.**
- 기간: 일간(가벼운 브리핑) / 주간(리포트) / 월간(수익 결산).
- **타겟 숫자 = baseline 쌓인 뒤(go-live 후 ~2주) 확정.** 그 전엔 측정만.

## 데이터 (분석의 밥)

### ★ 발행 이력(인벤토리) — go-live baseline (2026-11-10 대표)
**공장은 백지에서 시작하지 않는다.** 가동 전에 **지금까지 발행한 글들의 이력**을 한 번 정리해 baseline으로 깐다.
- **수집(1회) = 어사이드 (RSS 아님):** 어사이드가 **대표 본인 블로그**를 읽는다(내 블로그라 허용). 어사이드는 **제목·본문·통계탭 수치(조회수)까지** 다 뽑으니 RSS보다 완전 → 우리 블로그는 어사이드. (RSS는 '남의 참고 인플 공개 목록' 전용.) 사업부별(경제부터).
- **조회수:** 통계탭의 **현재 누적 스냅샷**은 넣는다(과거 추이는 아님 — 추이 측정은 go-live부터).
- **발행이력 칸:** `발행일 · 제목 · 키워드/주제 · 테마 · 제목유형 · 조회수(현재누적) · 링크 · 한줄요약`
  - **제목유형**은 제목담당이 분류(단일/혼합).
  - **한줄요약**은 글담당이 '순환검증(엮기)' 때 쓸 수 있게 핵심만.
- **쓰임 (세 담당이 참조):**
  - **키워드담당** → 이미 쓴 주제 **중복 방지**.
  - **제목담당** → 쌓인 제목 **유형 분류·패턴** baseline.
  - **글담당** → 관련 과거 글을 **엮어 녹임**(순환검증 = 사람이 쓴 느낌).
- **저장:** `기록/발행이력.md`(go-live 후 새 글마다 한 줄 append → 살아있는 문서). 지휘: `.claude/commands/경제-발행이력정리.md`.

### 성과로그 (go-live 후)
- 성과는 **네이버 통계 화면**에만 있음 → **어사이드**가 읽어 **성과로그**에 기록(권한·로그인은 기술보안팀 관리). 전체 체계 **구축 완료 후 go-live 시점부터** 매일 쌓기.
- **성과로그 칸:** `발행일 · 키워드 · 제목 · 테마 · 측정일 · 조회수 · 홈판유입% · 제목유형 · 후킹메커니즘`
  - 같은 글을 여러 날 측정(측정일마다 한 줄) → 추이 자동.
  - 제목유형·후킹메커니즘은 **발행 후 제목담당이 분류** → **후킹 라이브러리 성과가중**으로 되먹임(터진 후킹 ↑).

## 참고용 블로그 (= 배우는 대상, 경쟁 아님 / 다들 인플루언서)
- 쓸 수 있는 것: **공개된 글 목록(빈틈 주제)**, **공개된 제목(패턴 비교)**.
- 못 쓰는 것: 남의 **조회수**(비공개). 댓글·반응도 **영향 작음(대표 확인) → 안 씀.**

## 기술/보안팀 (크로스커팅 — 공장 안 멈추게)
- **임무:** 공장 안 멈추게. **드라이브 바통을 감시**해 멈춤 감지 → **Claude/GPU/파일 쪽은 직접 복구**(재시도·재시작), **어사이드/브라우저 쪽은 Claude가 못 누르므로 상태판 🔴 기록 + 대표 즉시 알림 + 작업 드라이브 보관→재개**(로그인 풀림·2FA·비번 등).
- **🚫 절대선:** 계정 비번(네이버·클로드·그록) **저장·자동 로그인 금지**(로그인 자동화 금지·네이버 ToS 계정정지 위험·2FA로 막힘·유출 리스크). **비번은 대표만.** API 키류만 Secrets. 승인 범위 밖(결제·계정설정·발행)은 승인 말고 보고.
- 반복 풀림은 패턴으로 짚어 근본 대책 제안. (에이전트: `기술보안팀`)
