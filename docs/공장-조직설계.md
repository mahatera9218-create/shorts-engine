# 집 PC 공장 — 조직 설계도 (체계)

*2026-11-10 · 살아있는 문서(설계 중 계속 갱신). 인프라·설치는 `집PC-공장-로드맵.md`, 설치 패키지는 `../local-factory/`.*
*대표가 "백지에서 한땀씩" 설계 중. 경제 블로그를 템플릿으로 세우고 다른 제품으로 확장.*

## 피라미드 조직
```
대표 (CEO) — 결정·발행
 └ 운영총괄 (Claude/COO) — 전체 조율
     ├ 전략본부   — 대표 비서실 (아래)
     ├ 분석본부   — 뭘·어떻게 (아래)
     └ 생산본부   — 글·사진·저장 (설계 예정)
```

## 전략본부 (= 대표 비서실)
- 분석본부 날것을 대표가 **보고 바로 판단하게** 요약·브리핑.
- 대표가 **이미 아는 것(조회수·발행편수)은 빼고**, **못 보거나 챙기기 번거로운 "숨은 것"**을 파냄.
- 단순 보고 X → **KPI 대비 방향, 대표가 생각·고려할 점까지 조언.**
- **시점별로 뭘 보고할지는 본부가 스스로 판단**(일=가볍게, 주=리포트, 월=결산). 톤은 읽기 쉽게.

## 분석본부
- **분석총괄(lead):** 성과로그 전체 조망 → 두 담당 결과 **종합해 제안 1개** → 대표. **순환 검증**(지난 제안이 먹혔나 재평가 / PDCA).
- **키워드 담당:** 뭘 쓸지. 핫키워드 선정 + **도전 키워드 1편 제안**(대표 승인) + 참고 인플에서 **빈틈 주제**.
- **제목 담당:** 발행된 제목을 읽고 **유형 분류(단일/혼합)** → 어느 유형이 조회·홈판 잘 나오나 + **참고 인플 제목과 비교**(제목은 공개라 비교 가능).

## 생산본부
글 한 편의 공정: 조사 → 글 → 사진 → 저장.
```
생산총괄
 ├ 조사 담당   (그록 — 현재 사실·단지 실거래·사연)
 ├ 글 담당     (클로드 — 제목+본문, 스킬: money-content-writer + blog-voice)
 ├ 사진 담당   (로컬 GPU/ComfyUI + 클로드 장면 프롬프트)
 └ 저장 담당   (네이버 임시저장)
```
- **저장 담당 = 클로드 크롬 확장 '후보', 어사이드 폴백.** 어사이드 환경이 불안정 + 브라우저 팔을 하나(크롬 확장)로 통합하려는 것. **단 리스크:** 네이버 에디터 조립(사진 순서 삽입·인용구 소제목·캡션 제거·단락)은 어사이드의 검증된 강점 → go-live 때 크롬 확장으로 **저장 테스트** 후 결정(깔끔하면 대체, 애매하면 그 부분만 어사이드 유지).
- **임시저장까지만. 발행은 대표.**

## 본부간 협업체계 (운영총괄 직접 지휘 = 허브)
본부끼리 **직접 대화 X.** **산출물(문서·시트)로 넘기고, 운영총괄(COO)이 순서를 돌리고 조정**한다. 닫힌 루프(PDCA).
```
분석본부 ─「오늘 생산지시」→ 생산본부 ─임시저장→ 대표(발행)
   ▲                                              │
성과로그 ←─ 크롬확장(발행결과 기록) ←─────────────┘
   │
   └→ 분석본부(평가) ─「분석 종합」→ 전략본부 ─「브리핑」→ 대표
```
| 본부 | 읽는 것 | 내놓는 것(핸드오프) |
|---|---|---|
| 분석본부 | 성과로그·참고인플 | 「오늘 생산지시」(키워드5+제목유형 권고+도전1) |
| 생산본부 | 오늘 생산지시 | 임시저장 글 + 생산로그 |
| 크롬확장 | 발행 결과 | 성과로그 |
| 분석본부 | 성과로그 | 「분석 종합」 |
| 전략본부 | 분석 종합 | 「대표 브리핑」(일/주/월) |
- **운영총괄 = 지휘자:** 각 본부 제때 깨움, 충돌 조정, 핸드오프 누락 감시. 본부는 서로 직접 호출하지 않음(허브-앤-스포크).

## 키워드 선정 로직 (날 단위)
- **핫키워드 날**(5편 다 핫) ↔ **틈새표 날**(5편 다 틈새), **2일 간격 교대.**
- 핫키워드 = **조회수 데이터에서 자동 선정**(분석본부). 같은 핫키워드는 2일 간격 재사용.
- 틈새표 = 기존 방식(검색량 상위 + 부동산3·바이오2 + 2일 중복제외).
- 가끔 **도전 키워드 1편**을 에이전트가 이유와 함께 제안 → 대표 승인 시 반영.

## KPI 뼈대
- **북극성(결과) = 애드포스트 수익.**
- **선행 = 조회수**(직접 미는 레버, 수익을 끌어올림).
- **돈줄 드라이버 = 홈판 노출.**
- 기간: 일간(가벼운 브리핑) / 주간(리포트) / 월간(수익 결산).
- **타겟 숫자 = baseline 쌓인 뒤(go-live 후 ~2주) 확정.** 그 전엔 측정만.

## 데이터 (분석의 밥)
- 성과는 **네이버 통계 화면**에만 있음 → **클로드 크롬 확장**이 읽어 **성과로그 시트**에 기록(어사이드보다 유연). 전체 체계 **구축 완료 후 go-live 시점부터** 매일 쌓기.
- **성과로그 칸:** `발행일 · 키워드 · 제목 · 테마 · 측정일 · 조회수 · 홈판유입% · 제목유형`
  - 같은 글을 여러 날 측정(측정일마다 한 줄) → 추이 자동.
  - 제목유형은 **발행 후 제목 담당이 분류**(단일 또는 혼합).

## 참고용 블로그 (= 배우는 대상, 경쟁 아님 / 다들 인플루언서)
- 쓸 수 있는 것: **공개된 글 목록(빈틈 주제)**, **공개된 제목(패턴 비교)**.
- 못 쓰는 것: 남의 **조회수**(비공개). 댓글·반응도 **영향 작음(대표 확인) → 안 씀.**

## 원칙 (불변)
- 발행·외부공개 = 대표 수동. 수집은 허용된 통로만. 가짜·날조 ❌.
- 계산·수집 = 코드, 판단·창작 = LLM.
