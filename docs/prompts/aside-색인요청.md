# Aside 지시문 — 새 글 색인 요청 (네이버 서치어드바이저 · 구글 서치콘솔)

목적: 새로 발행·수정한 글을 검색엔진이 빨리 알게 한다. **소량만**(하루 합계 5개 안팎, 사람이 하는 속도로) — 대량·반복 요청은 품질 신호에 불리하다.

전제: Aside 브라우저에 대표의 네이버·구글 계정이 로그인돼 있어야 한다. 로그인·인증·결제 화면에서는 멈추고 대표에게 묻는다.

```text
오늘 astacgroup.com에 새로 발행되거나 수정된 글 주소를 찾아서 아래 순서로 색인 요청을 해 줘. 하루 합계 5개를 넘기지 말고, 같은 주소를 반복 요청하지 마. 로그인·보안 확인 화면이 나오면 멈추고 나에게 알려 줘.

1) 오늘 요청할 주소 목록 만들기
- https://astacgroup.com/sitemap.xml 을 열어 lastmod가 오늘 또는 어제인 글 주소(홈·카테고리 제외)를 최대 5개 고른다.
- 이미 어제 요청한 주소는 빼고, 고른 주소 목록을 나에게 먼저 보여 준다.

2) 네이버 서치어드바이저 (searchadvisor.naver.com)
- 사이트 'astacgroup.com' 선택 → 요청 → 웹 페이지 수집 → 주소를 하나씩 넣고 '확인' → 수집 요청.
- 요청이 접수됐다는 메시지(또는 한도 초과 메시지)를 주소별로 기록한다. 한도 초과가 뜨면 즉시 멈춘다.

3) 구글 서치 콘솔 (search.google.com/search-console)
- 속성 'astacgroup.com' 선택 → 위쪽 검색창에 주소 입력(URL 검사) → '색인 생성 요청'.
- '이미 색인됨'이면 요청하지 않는다. 할당량 초과 메시지가 뜨면 즉시 멈춘다.

4) 결과를 표로 보여 줘: 주소 | 네이버 요청(접수/한도초과/건너뜀) | 구글(요청/이미 색인/건너뜀). 해낸 일과 못 한 일을 숨기지 말고 적어.
```

## 참고 (왜 이렇게 하나)
- 네이버는 사이트맵·RSS 제출과 IndexNow(코드가 발행 때 자동 전송, `content/indexnow.py`)로 이미 알리고 있어서, 이 수동 요청은 **보조**다.
- 구글은 IndexNow를 지원하지 않는다. 사이트맵·내부 링크가 기본이고 URL 검사 '색인 생성 요청'은 소량 보조다. Indexing API는 구인공고·라이브 영상 전용이라 쓰지 않는다.
- **네이버 블로그 글을 구글에 색인 요청하는 것은 불가능하다**: blog.naver.com은 대표 소유 도메인이 아니라 서치 콘솔 속성으로 등록·인증할 수 없다. 구글이 알아서 수집하며, 우리가 할 수 있는 건 링크를 걸어 발견 경로를 늘리는 것(예: 사이트에 블로그 새 글 링크 모음)뿐이다.
