# 네이버 기준·홈판 최적화 종합 점검 (2026-10-11)

대표 요청: "현재 전체 수준이 네이버 기준에 맞는지, 홈판 노출에 최적화돼 있는지, 이대로 글만 쌓으면 되는지 냉정하게."

## 한 줄 결론

**아니요, 이대로 글만 쌓으면 안 됩니다.** 글 품질 장치는 꽤 갖췄지만, ① **홈판에 실제로 떴는지 데이터가 0건**이라 지금까지 6일·43편이 전부 눈 감고 한 것이고, ② **네이버 검색 API 약관(2026-09 개정) 위반 소지**가 있으며, ③ **같은 주제 반복·같은 날 거의 같은 글**이 있어 피드·유사문서 면에서 손해 볼 수 있습니다. 이 셋을 먼저 고치고 나서 쌓아야 합니다.

## 🔴 1. 성과 데이터가 0건 — 가장 큰 문제

- 확인: 블로그 통계 저장 폴더(`econ/stats/`)가 **아예 없음**. 2026-10-08에 정한 "어사이드가 매주 월요일 통계 올리기"가 **한 번도 안 들어왔습니다.**
- 그래서 지금까지 한 점수 조정(화제성·최신성·블로거 가중치, 썸네일 실사/자극 등)은 **전부 근거 없이 감으로** 한 것입니다. 홈판에 뜬 글이 1편인지 0편인지도 모릅니다.
- 발행 완료 표시도 43편 중 11편만 돼 있어, 실제 몇 편이 올라갔는지도 불분명합니다.
- **홈판 전략(2026-10-10)의 4번째 기둥 '검증'이 비어 있으면 나머지 셋도 튜닝이 불가능**합니다.

**개선**
1. 이번 주부터 **통계를 반드시 받기**: 어사이드 주간 통계(조회·유입경로·글별 조회) → `[블로그통계]` 이슈. 안 되면 대표님이 **글별 조회수만이라도 주 1회 캡처**.
2. 최소 지표 3개만 봅니다: **글별 조회수 · 유입경로 중 '홈/피드' 비중 · 발행 후 24시간 조회수**.
3. 데이터 2주(약 30편) 쌓이기 전에는 **점수 가중치를 더 바꾸지 않기**(지금 바꿔도 맞는지 판단 불가).

## 🔴 2. 네이버 검색 API 약관 위반 소지

- 보도(뉴스웨이·TokenPost·한국데이터경제신문, 2026-09) 기준: 네이버 검색 API 특약 개정이 **2026-09-07(개발자센터)·09-20(API HUB 추정)** 시행. 요지:
  - 검색 API로 받은 데이터를 **AI에 입력하거나 학습·개선·평가·노출에 쓰는 것 금지**
  - **복사·저장·캐싱 제한**, 제3자 제공·수익화 금지, 이용 목적은 "검색 결과를 앱에서 보여주는 것"으로 제한
  - 데이터랩(검색어트렌드·쇼핑인사이트)은 별도라는 정리가 있음
  - ⚠️ 원문 약관은 이 환경에서 못 열었음 → **API HUB 콘솔에서 원문 확인 필요**
- 우리 코드 대조:

| 쓰는 곳 | 내용 | 판단 |
|---|---|---|
| 패션 `news_queries` | 네이버 **뉴스 검색 제목 → Claude 묶기 프롬프트** | 🔴 AI 입력 — 위반 소지 큼 |
| 도우미 패션 '같은 키워드 블로그 글 3개' | 블로그 검색 결과를 정적 페이지에 박아 배포 | 🟠 저장·캐싱 회색 |
| 도우미 '인물 사진 후보' | 이미지 검색 결과를 정적 페이지에 박음 | 🟠 저장·캐싱 회색 |
| 점수의 뉴스·블로그 24시간 건수 | 숫자만 점수에 사용, 키워드 파일에 저장 | 🟡 파생 데이터 저장 회색 |
| 검색어트렌드·쇼핑인사이트·검색광고 | 데이터랩·검색광고 API | 🟢 특약 대상 아님(보도 기준) |
| 블로거 RSS·Grok·Claude 웹검색 | 검색 API 아님 | 🟢 |

- 위험: 위반이 걸리면 **API 키 정지** → 키워드 점수(뉴스·블로그 건수)·사진 후보가 한꺼번에 멈춤. CLAUDE.md "허용된 통로로만 수집"에도 어긋남.

**개선(대표 결정 필요)**
1. **즉시**: 패션 `news_queries` 제목을 AI에 넣는 경로를 끄고, 연예 **RSS**와 Grok 웹검색으로 대체.
2. 도우미의 블로그 글 3개·인물 사진 후보는 **결과를 페이지에 박지 말고 '네이버에서 검색' 링크**로 바꾸기.
3. 24시간 건수는 점수 계산에만 쓰고 **원자료는 저장하지 않기**(점수만 남김).
4. 대표님이 API HUB 콘솔에서 **검색 API 이용약관 개별 특약 원문** 한 번 확인 → 원문대로 설계서 고정.

## 🟠 3. 같은 주제 반복·같은 날 거의 같은 글

| 사례 | 내용 |
|---|---|
| 10-08 | '삼성전자 3분기 실적 발표' + '삼성전자 3분기 영업이익 10조' — **같은 날, 둘 다 1,383자** |
| 10-11 | '스페이스X 상장' + '스페이스X 상장 투자 방법' — 같은 날 |
| 6일간 | 삼성전자 4번, 비트코인 3번(3일 연속), SK하이닉스·나스닥 각 2번 |
| 패션 | 17편 중 **샤넬 8편**, '전도연 샤넬 드레스' 이틀 연속 |

- 왜 생기나: '이미 쓴 주제 거르기'가 **월 검색 20만 이상은 예외**라서 삼성전자 같은 초대형 키워드는 계속 통과. 또 대표님이 직접 고르는 키워드는 거르지 않음.
- 왜 문제인가(2차 자료 공통 지적, 공식 아님): 같은 블로그 안의 비슷한 글은 서로 노출을 깎고(자기잠식), 피드 쪽에선 "관심없음"을 부르기 쉬움. 2026 탐색 피드는 '관심없음' 버튼이 생김.

**개선**
1. **같은 날 같은 회사·같은 사건 2편 금지**(코드로 막기). 둘째 글은 다음 날로 미루거나 첫 글에 합치기.
2. 초대형 예외를 "**같은 각도면 3일, 다른 각도(실적↔주가↔배당)면 허용**"으로 좁히기.
3. 패션: 같은 브랜드 하루 1편, 같은 인물+같은 아이템은 7일 안 반복 금지.

## 🟠 4. 홈판 승부처(썸네일·제목) 검증 0

- 홈판 전략 문서도 "**CTR이 전부**, 썸네일·제목이 진짜 승부처"라고 정했는데, 지금은 썸네일을 대표님이 프롬프트로 직접 만들고 **어떤 썸네일이 클릭을 받았는지 기록이 없음**. 이번 주에만 썸네일 방향이 '자극적 → 실사'로 바뀌었는데 이것도 데이터 없이 바뀜.
- 제목 8유형은 있으나 **어떤 유형이 클릭을 받았는지 모름**(성과탭 '벼려내기'는 데이터가 없어 빈칸).

**개선**
1. 글마다 **제목 유형·썸네일 방식(실사/자극)·발행 시간**을 기록(이미 chosen.yaml에 일부 있음) → 통계 들어오면 자동 비교.
2. 2주간 **썸네일 A/B**: 같은 섹션에서 실사 vs 강한 연출 번갈아 → 24시간 조회수로 판정.

## 🟡 5. 문체 — AI 티

- 경제 26편: 문장 끝 '~습니다/~입니다' 비율이 **30~60%**(같은 어미가 연달아). 2차 자료들이 공통으로 꼽는 "반복적·기계적 문장"에 해당.
- 오늘 넣은 장치(첫 글쓰기부터 어미 반복 금지 + 편집장 2회)는 **새 글부터** 적용 → 다음 1주 측정해서 30% 아래로 내려오는지 확인.
- 패션은 13~29%로 상대적으로 양호.

## 🟡 6. 생산량 vs 새 블로그

- 6일 동안 경제 26편·패션 17편 생성(하루 7~8편). 2차 자료들은 "대량 자동 생성"을 제재 대상으로 공통 지목(공식 수치 없음).
- 새 블로그는 신뢰가 쌓이기 전이라 양보다 **편당 완성도**가 유리하다는 게 일반적 관측.

**개선**: 통계가 들어오기 전까지 **블로그당 하루 2편**(9시·18시)으로 줄이고, 아낀 노력을 썸네일·제목에. 데이터로 "많이 올려도 노출 유지"가 확인되면 다시 늘림.

## 🟢 잘 되고 있는 것

- **원칙 지키기**: 가짜 경험 금지, 패션 착용 확인 게이트, 투자 권유 문구, AI 이미지 고지 — 네이버 신뢰 면에서 안전한 쪽.
- **구조 일관성**: 원문 체크로 소제목·표·Q&A·사진 수가 일정.
- **품질 장치**: 처음부터 기준 지켜 쓰기 + 편집장 검수 + 2단계 고쳐쓰기(비용 통제).
- **키워드 체계**: 화제성·최신성(블로거·어사이드)·수요 2:1:1은 홈판 방향과 맞음 — 다만 검증 전.
- **비용**: 월 약 15만원 페이스, 상한 안.

## "이대로 글만 쌓으면 되나?" — 답

**아니요.** 지금 구조는 "좋은 글을 꾸준히 만드는 공장"까지는 왔지만, **홈판은 결국 클릭과 반응으로 밀어주는 곳**이고 그걸 볼 눈(통계)이 없습니다. 지금 쌓으면 (1) 먹히는지 모르는 글을 계속 찍고, (2) 반복 주제로 서로 깎아 먹고, (3) API 약관 리스크를 안고 갑니다.
