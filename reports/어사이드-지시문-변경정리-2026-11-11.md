# 어사이드 지시문 변경 정리 — 원래 → 바뀜 → 왜 (2026-11-11)

경제 루틴 기준. 각 항목을 **① 원래 이랬다 → ② 이렇게 바뀐다 → ③ 왜** 순으로.

---

## 변경 1. 구조 — 올인원 → '수집 / 저장' 둘로 분리

**① 원래:** 어사이드 하나가 전부 함. 틈새표 키워드 → 그록 조사 → **클로드 웹**(「쿠니 경제」)에서 글·제목·사진장면 → **지피티 웹**에서 사진 → 네이버 조립·임시저장 → 시트 기록. 전 과정이 브라우저 탭을 오가는 복붙.

**② 바뀜:** 어사이드를 둘로 쪼갠다.
- `aside-경제-수집`: 모드·키워드 + **그록 조사** → **드라이브 `N_조사.md`** 에 떨굼. (여기서 멈춤)
- `aside-경제-저장`: **드라이브 `N_원고`·`N_사진/`** 를 읽어 → 네이버 조립·임시저장(표·단락·서식·카드 노하우 전부 유지) + 시트.
- 가운데(글·제목·사진·검수) = **Claude Code.**

**③ 왜:** 글쓰기를 Claude Code로 옮겨야 **스킬(AI티 검사)·검수 게이트·순환검증·후킹 라이브러리**가 자동으로 돈다. 어사이드가 클로드 웹을 탭으로 돌리면 그게 안 된다. 손발(어사이드)과 두뇌(Claude)를 드라이브로 잇는 게 공장의 핵심.

---

## 변경 2. 사진 — 지피티 웹 → GPU 생성 + 그록 편집

**① 원래:** B-2단계에서 **지피티 「경제 사진」** 탭 2~3개로 사진 생성.

**② 바뀜:** 지피티 폐기.
- 생성컷(금괴·제품·공장·무드) = **로컬 GPU**(ComfyUI RealVisXL, 1024²).
- 썸네일·실물컷(단지·역·기관·간판) = **그록이 수집→선별→편집**(1024²).

**③ 왜:** 지피티는 비용·통제 문제 + '맨땅 상상'이라 단지·대상이 틀렸다. GPU는 공짜·무제한·실사 검증됨(어제 통과). 정체성 사진은 그록 실물이라야 정확(생성하면 간판 글자가 가짜로 깨짐 — 테스트로 확인).

---

## 변경 3. 바통 — 브라우저 복붙 → 드라이브 파일

**① 원래:** 그록 조사를 **클로드 웹에 붙여넣기**, 클로드 글을 **네이버에 붙여넣기**. 전부 브라우저 안에서 손으로 오감.

**② 바뀜:** 그록 조사 → **드라이브 `N_조사.md`**. Claude Code 원고 → **`N_원고.md`**. 어사이드가 그걸 읽어 저장. (붙여넣는 '목적지'만 바뀜: 웹 탭 → 드라이브 파일.)

**③ 왜:** 외부 Claude Code와 어사이드(브라우저)는 **직접 대화 못 한다.** 그록도 API 아닌 웹이라 어사이드 안에 있다. **드라이브가 둘을 잇는 유일한 통로.** 어사이드는 이미 시트에 쓰므로 드라이브 저장은 검증된 능력.

---

## 변경 4. 상태판·지시함 — 없음 → 추가

**① 원래:** 없음. 대표가 공장이 어디까지 됐나 못 보고, 밖에서 지시도 못 던짐.

**② 바뀜:**
- 수집 **시작 시 `지시함.md` 확인** → 대표가 던진 지시 반영.
- **단계마다 `상태.md`에 한 줄** 기록(멈추면 🔴+이유).

**③ 왜:** 공장이 무인으로 도니 대표가 **폰에서 상태 확인·지시**할 창구가 필요. PC 꺼져 있어도 지시함(드라이브)에 쌓였다 다음에 반영. 이게 대표의 눈·입.

---

## 변경 5. 사진 수집 방식 — 그록 URL+지피티 보완 → [실물]플래그+그록 편집

**① 원래:** 그록이 준 URL로 사진 받고, 부족분은 지피티 보완컷.

**② 바뀜:** 글담당이 [사진 장면]에 **`[실물]` 플래그**(특정 단지·역·기관·간판 + 썸네일 항상) → 그록이 **3~5장 수집 → 최고 1장 → 편집**(간판 유지·글 분위기별 톤·1024²).

**③ 왜:** GPU로 억지로 그리면 간판·건물이 깨진다(img2img 폐기 이유). 실물이 정확. 수집은 좁게(토큰) 대신 **편집에 힘줘** 블로그 획일화 방지.

---

## 변경 6. 제목 — 자체 12개 → 후킹 라이브러리 응용

**① 원래:** 클로드 웹에서 4유형 × 3 = 12개를 **우리 틀로 짜냄.**

**② 바뀜:** 제목담당이 **후킹 라이브러리**(인플 ""·'' 후킹 매일 학습) 를 오늘 글에 **응용** → 서로 다른 결의 후보. **33자 이내·후킹 앞 10자(키워드 앞서면 15자) 안.** 발행 성과로 터진 후킹 강화.

**③ 왜:** 우리 틀로만 지어내 매일 뻔했고, 12개가 한 틀이라 섞을 게 없었다. 인플한테 배우고 성과로 검증해야 신선하고 먹히는 제목이 나온다.
