# 공개 지표 비교(순위) — 운영 구조와 데이터 소스 (2026-10-18)

## 1. 한 줄 정의
종합 점수·순위 없이, **출처가 있는 공개 지표**를 항목별로 나란히 보여 주는 비교 페이지(/rank). 근거 없는 항목은 화면에서 숨긴다.

## 2. 데이터 소스 (이미 쓰는 인프라 위주, 추가 비용 0원)
| 항목 | 소스 | 수집 방식 | 주기 | 신뢰도·한계 |
|---|---|---|---|---|
| 인지도 | 네이버 검색광고 API(`NAVER_AD_*`) 월간 검색수 PC+모바일 | 자동(content/rank_metrics.py) | 주 1회 | 실측 수치. 브랜드 키워드 기준이라 동음이의어 주의(예: '토스 환급'으로 한정) |
| 최근 관심도 | 네이버 API HUB 데이터랩 검색어 트렌드(`NCP_APIGW_*`) 주간 상대값 | 자동 | 주 1회 | 같은 요청 안 최댓값=100인 상대값. '품질'이 아닌 '관심' |
| 앱스토어 평점 | 애플 iTunes Search API(공개·무인증) | 자동 | 주 1회 | 평가 1,000건 미만 제외. 앱 전체 평점(슈퍼앱은 서비스 단독 평점 아님, 라벨에 명시). 구글플레이는 공식 API 없어 제외 |
| 수수료·운영사 등 사실 | 각 서비스 공식 페이지 | **사람이 확인 → 링크·확인일과 함께 입력**(양식: reports/순위-사실표-입력양식.md) | 변경 시/분기 | 공식 문구 그대로, 블로그·기사 인용 금지 |
| 표시광고·제재 이력(후속) | 공정위 보도자료 원문 | 수동 | 사건별 | 확정 사건만, 날짜·링크 필수. 신고·주장은 반영 금지 |
| 보험 공식 서비스 | 생·손보협회 '내보험찾아줌' 등 | 수동 링크 | - | 공식 서비스는 순위 대상이 아니라 안내 박스 |

쓰지 않는 소스: Grok/AI 추정 점수, 블로그·후기 크롤링, 구글플레이 스크래핑, 구글/네이버 지도 평점 저장(약관 제한).

## 3. 운영 흐름
```
[매주 월 07:23 KST, GitHub Actions: 순위 자동 지표 주간 수집]
  rank_metrics.py → 검색광고 API / 데이터랩 / iTunes 호출
  → web/content/rankings/<분류>.json 에 점수 + evidence(출처·값·확인일) + history(주간 기록) 기록
  → rank_verify.py(검증 게이트) 통과 시에만 main 커밋 → Vercel 자동 배포 → 사이트 반영
[수시, 대표 입력] 수수료·운영사 사실 + 공식 링크 → 저(Claude)가 facts에 입력 → 검증 → 배포
```
- 키가 없거나 API 오류면 기존 값 유지(안전). 수집 실패가 사이트를 깨지 않는다.
- 수동 실행: Actions → '순위 자동 지표 주간 수집' → Run workflow.

## 4. 데이터 구조 (web/content/rankings/<분류>.json)
- `criteria[]`: 항목 key·이름·설명(note). 가중치·종합점수 없음.
- `apps[]`: slug·name·tag·summary·url, `metrics`(수집 설정: keyword, apple_term, apple_seller), `scores{항목:0~5}`, `evidence{항목:{type: auto|manual, source, label, url, checked}}`, `facts[{label,value,url,checked}]`, `history[{date,volume,interest}]`(최대 52주), `pending`.
- 규칙: 점수가 있으면 반드시 evidence. 수동 근거·facts는 https 링크 필수.

## 5. 검증 게이트 (rank_verify.py, 매 수집·CI)
- 점수 0~5, 알 수 없는 항목 금지, 모든 점수에 근거, 수동 근거·facts는 https 링크.
- 공개(beta:false) 조건: status='verified'이고 근거 있는 점수나 사실이 하나 이상, 평가 대기 대상 공개 금지.
- 화면: 값이 없는 항목은 숨김. 근거 확인 항목 수 표시.

## 6. 화면 구조 (모바일 우선)
- /rank 허브: 분류 행(세무법인·법무법인·세무앱·보험앱), 분류당 3곳 + '더보기'(최대 10).
- 분류 페이지: 한눈에 보기 → 공개 지표 비교(항목 탭 선택 시 값 순 정렬, 막대+근거 라벨) → 확인한 사실 표 → 검색 관심도 추이 그래프 → 관련 해설 글 → 비교 방법.
- 앱 상세: 항목별 값과 근거, 사실, 추이, 공식 링크(제휴는 표기).
- 지금은 베타(색인 제외). 근거 있는 값이 쌓이고 검증을 통과하면 beta:false로 공개 전환.

## 7. 분류별 현재 상태
| 분류 | 상태 | 비고 |
|---|---|---|
| 세무앱 | 자동 지표 설정 완료(삼쩜삼·토스·홈택스), **첫 수집 전** | Actions 실행 필요. 세이브택스는 평가 대기 |
| 보험앱 | 후보 3곳 평가 대기 | 공식 서비스(내보험찾아줌)는 안내 박스 성격 |
| 세무법인·법무법인 | 준비 중(대상 없음) | 서열 금지. 공식 조회 링크·자격·징계 공고 중심의 사실표만 검토(법적 위험: 변호사·세무사 광고 규정) |

## 8. 운영 체크리스트
- 매주: 월요일 수집 성공 여부(Actions 초록 체크), 값 급변 확인.
- 월 1회: 수수료·운영사 사실의 공식 링크 유효성·확인일 갱신(대표 확인 → Claude 입력).
- 분기: 평가 항목·키워드(검색어) 점검, 신규 후보 추가 여부 검토.
- 공개 전환 전: rank_verify 통과 + 사실표 최소 3항목 + 해설 글 발행 + 면책·광고 표기 점검.

## 9. 위험과 대응
| 위험 | 대응 |
|---|---|
| 얇은 자동 페이지로 보임(애드센스·검색 품질) | 베타(색인 제외) 유지, 사실표·추이·해설 글로 가치 보강 후 공개 |
| '관심도=좋은 서비스'로 오해 | 화면·방법 설명에 '품질 아님' 명시, 종합 점수 없음 |
| 법적 분쟁(명예훼손·표시광고) | 점수 합산·서열 없음, 근거·확인일·링크 표기, 확정 사건만 인용, 정정 요청 이메일 |
| API 오류·키 만료 | 실패 시 기존 값 유지, Actions 로그로 확인 |
| 제휴 링크 | rel=sponsored 및 문구 표기, 지표에 영향 없음 |
